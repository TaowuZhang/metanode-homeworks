## 0. 边界

本轮不是腐海主脊柱复审，也不是技能体系重写。它只处理以下词簇在技能调度支路中的历史残留与误导风险：

- 授权
- 红线
- 守门
- 操缦
- 退场
- 施工自述
- 旧主脊柱惯性

本轮不处理：

- 腐海七判去留的新论证；
- 星盘 / 公约数 / 破晓台 / 栈桥的全局重审；
- 页面移动、归档、删除；
- 数据库结构调整；
- 主线合并或发布动作。

## 2. 残词判准

| 词簇 | 保留条件 | 清理条件 | 本轮口径 |
|---|---|---|---|
| 授权 | 指真实工具 / 协作授权差异，且与价值判断分清 | 暗示“工具能做 = 已获协作授权” | GitHub 报告可保留；Notion 活页优先写“价值判断 / Checkpoint / 停问谷” |
| 红线 | 指不可逆、公共后果、关系动作等硬边界 | 抽象禁忌清单，压过当前“价值判断”结构 | 工具页已改成“没有抽象红线清单”；子页若是领域硬边界可保留或改成“硬边界” |
| 守门 | 明确 checkpoint、停问谷或价值判断位置 | 泛化成处处请示、阻断径行 | 当前有效词优先为 Checkpoint / 放行 / 停问谷；“守门者=人”若为角色字段可保留 |
| 操缦 | 作为历史旧称可追溯 | 继续作为当前主名，压过「技能：技艺调度与双位流转」 | 活页中应统一为“技能总门 / 技能调度总门”，必要处写“旧称：操缦” |
| 退场 | 指对象生命周期、外运、墓碑化 | 误导成腐海主脊柱退场复审 | 技能页中未见需要重开；只在 GitHub 报告保留历史风险标签 |
| 施工自述 | 作为 GitHub 历史过程说明 | 留在 Notion 活页里，干扰冷启动执行 | 本轮历史过程只入本报告，不写回 Notion 活页 |
| 旧主脊柱惯性 | 仅作历史风险标签 | 重新展开七判 / 腐海主脊柱争议 | 本轮不展开；只作为越界提醒 |

## 5. A 级建议改动清单

这些改动均为局部改词 / 桥接句，不移动页面、不删整段、不改结构。已执行的项目见第 10 节。

1. **旧称统一**
   - `操缦总门` → `技能总门`
   - `作为操缦下` → `作为技能总门下`
   - `回操缦总门接法` → `回技能总门接法`
   - `操缦守门` → `技能总门 Checkpoint / 停问`

2. **员额惯性清理**
   - `暂不计入十一技` → `暂不计入基干技名单`
   - `第十二技` → `新增基干技 / 扩展技候选` 或直接删去数字
   - `是否明确不计入十一技` → `是否明确不计入基干技名单`

3. **红线 / 守门弱化为当前结构**
   - `权限与守门` → `Checkpoint 与放行`
   - `红线与警报` → `硬门槛与警报`
   - `落库红线` → `落库硬边界`
   - `守门显化` → `防偏自检显化`

4. **工具授权桥接**
   - 涉及“协作授权”的页，补一句短桥接：`工具可用性 ≠ 价值判断；候选施工可径行，主线 / 发布 / 权限 / 关系动作按 Checkpoint 停问。`

## 7. 未改动但保留理由

- `工具页` 中“没有抽象红线清单”保留：这是当前有效结构。
- `机括` 中“价值判断点”保留：与工具页一致。
- `过闸 / BibiGPT 取水 / 临发` 中的 A/B 与硬边界多数保留：这些页面本身处理入口闸门或发布前放行，风险尺度真实存在。
- `审计` 中的 A/B / 守门节点保留：这是形成过程审计的检查项，用于发现旧门禁漂移，不等于当前日常动作都要守门。
- GitHub 旧报告里的“操缦 / 倒缆 / 红线 / 授权”保留：历史沉积不改词，避免破坏可追溯性。

## 8. 风险与回退

### 风险

1. **机械清词风险**：把所有红线 / 守门都删掉，会破坏发布、入库、编校等真实放行结构。
2. **旧称回潮风险**：若子页继续写“操缦总门”，新总门名会被历史名反压。
3. **员额回潮风险**：十一技 / 第十二技 会重新制造“数目就是结构”的误读。
4. **报告滞留风险**：如果报告停在 GitHub、不回 Notion，活页仍会继续被旧词触发。

### 回退

- Notion 小补丁均为逐页小范围替换，可按本报告旧句回退。
- GitHub 本报告经 PR 合入后按 Git 历史回看。
- 若任何补丁触发“结构名 / 母本 / 总门层位”争议，停止 Notion 修改，只保留本报告。
