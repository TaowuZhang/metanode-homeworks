# 个人展示与网页外壳地图

这份文档给「个人 Notion 页 / 网页 / 社交分发」划展示边界。它不重写个人页面正文，也不替代 `docs/ops/distribution-map.md`。

## 总判准

> 本地负责生长，Notion 负责活体展示，网页负责门面，社交媒体负责排泄。

个人展示不是排泄。它不是把所有东西往外扔，而是给陌生访客一条能进入谷的路径。

## 三层出口

| 层 | 作用 | 回答的问题 | 真相源 |
|---|---|---|---|
| Notion 公共入口 | 活体自我介绍 | 现在有哪些正在发生的东西？ | Notion 展示层 + 本地摘要 |
| Web 首页 | 可控门面 | 3–10 秒内为什么值得继续看？ | 本地 / Notion 抽取 |
| 社交分发 | 外排触点 | 这坨东西能不能撞到外界？ | 发布包与外手日志 |

## Notion 公共入口

建议结构：

1. **脉搏**：KPI + OKR + 超越叙事。用来显示当前生命体征，不做完整档案。
2. **工作台**：正在推进的工程 / 学习 / 内容项目。只给卡片和下一步，不展开所有历史。
3. **陈列柜**：坐标故事与认知转折。用 Teaser → Depth，不用内部 Table 直接裸奔。
4. **联系**：邮箱 / GitHub / 社交入口，轻放。

不放：

- 温棚完整协议。
- 终端桥执行页。
- 收件箱。
- 未筛隐私的原始色散。
- 面向克的长期指令。

## Web 外壳

Web 不做第二套知识库。第一版只做外部门面：

- Hero：一句定位 + 当前状态。
- Pulse：从脉搏抽取 3–5 个活指标。
- Workbench：项目卡片。
- Cabinet：坐标故事精选。
- Dispatch：最近发布 / 排泄过的内容。
- Contact：联系入口。

技术原则：

- 静态站优先。
- 数据先来自本地 Markdown / JSON，不急 Notion API。
- Cloudflare Pages / Vercel 均可。
- 不做登录、评论、复杂 CMS。
- 不让网页成为新真相源。

## 设计原则

- 内部管理视图与外部展示视图分裂。
- 管理视图追求完整、可编辑。
- 展示视图追求 Teaser → Depth：先给好奇缺口，再给深层材料。
- 不把文艺感压成鸡汤；视觉用「温暖硬核 / 工业数据流 / 反差混搭」去对冲。
- 不为了陌生访客抹掉沃壤的怪，但要给入口，不把人直接扔进泥坑。

## 与发布包的关系

发布包服务社交分发。  
个人展示服务长期入口。  
网页服务门面与可探索结构。

三者可以共享材料，但不要共享状态机：

- 发布包可以短命、一次性。
- Notion 展示可以持续更新。
- Web 外壳应该稳定、轻、可迁移。
