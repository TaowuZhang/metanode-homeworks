# 潮汐底盘 v2 · 两个前台 v0

> 当前裁决：Notion 端已经收成早晨前台；GitHub 端接手晚上前台。人每天只看两个地方：早上 Notion Dashboard，晚上 GitHub 裁决台。

## 0. 两个前台

```text
早上：Notion 3.4 Dashboard = 今日开工
晚上：GitHub Projects = 晚上裁决
```

不要再把系统扩成页面堆、视图堆、说明堆。页面、数据库、issue、workflow 都只是后台材料。

## 1. 早上 Notion 前台（已落地）

名称：`☀️ 今日开工`

介质：Notion 3.4 Dashboard view。

### 第一屏

三列开工卡：

| 列 | 用途 |
|---|---|
| 直接做 | 谷现在就能动 |
| 交给克 | 克可以先跑，不等谷早上判断 |
| 今天占位 | 今天承认它在，但不抢第一刀 |

### 卡面只露四样

1. 行动
2. 接续之问
3. 火
4. 给克一句话

### 下沉内容

KPI、总表字段、锰感、节律、治理解释、历史草案全部下沉。数字只做超载提醒，不做早上的主语。

## 2. 晚上 GitHub 前台（本 PR 主刀口）

名称：`🌙 晚上裁决`

介质：GitHub Projects / issues。

### 六列

| 列 | 用途 | 晚上动作 |
|---|---|---|
| 待裁决 | 今晚必须看一眼 | 升 / 降 / 交 / 退 |
| 谷 WIP | 真在谷手上，占人的带宽 | 保留 / 降水位 / 退相干 |
| AI 可推进 | 克能先跑 | 分派给克 |
| 暂留 | 活着，但不该每天冒头 | 继续停泊 / 退相干 |
| 代谢台 | 排泄 / 拍摄 / 审计 / 喷射 | 做代谢判断 |
| 完成 / 退相干 | 出口 | 关账，不再占活现场 |

晚上只问：

```text
哪张升到明天 Notion？
哪张交给克？
哪张留在谷 WIP？
哪张暂留？
哪张退相干？
哪张需要排泄 / 拍摄 / 审计 / 喷射？
```

## 3. GitHub 字段

| 字段 | 用途 | 建议值 |
|---|---|---|
| Frontstage | 当前在哪个前台 | Notion morning / GitHub evening / backstage |
| Evening lane | 晚上六列 | 待裁决 / 谷 WIP / AI 可推进 / 暂留 / 代谢台 / 完成·退相干 |
| Waterline | 是否进明早 Notion | 今日 / 候补 / 水下 |
| Fire | 人还想不想要 | 烧 / 温 / 冷 |
| Morning prompt | 明早能复制给克的话 | 一句话 |
| Continuing question | 接续之问 | 一句问句 |
| Ritual | 代谢类型 | 无 / 巡检 / 排泄 / 拍摄 / 审计 / 喷射 / 栈桥候选 |
| Exit | 出口 | 未到出口 / 关 / 接 / 沉 / 退 |

## 4. 夜间裁决格式

每晚只产一张裁决纸条：

```text
升到明天 Notion：
交给克：
谷 WIP：
暂留：
代谢台：
完成 / 退相干：
一句理由：
```

这张纸条写回 GitHub。Notion 只接收「明天早上应该出现的 3–5 张卡」。

## 5. 后台规则归位

| 规则 | 归位 |
|---|---|
| Activity 动态治理 | GitHub 晚上六列的骨架 |
| 数字节律 | 只住代谢台 |
| 几点几坡度尺 | 判断动作尺度与不可逆度，不抢屏 |
| Notion Dashboard | 早晨前台 |
| 普通页面 / 旧草案 | 维修口 |

## 6. 验收标准

### Notion 端

已完成第一版：早上打开只看 `☀️ 今日开工`。

### GitHub 端

本 PR 通过后，应能支持：

- 新 issue 开户时直接标注晚上六列。
- AI 能知道哪些可以推进，哪些必须等谷裁决。
- 代谢动作不会混进早上 Notion。
- 完成 / 退相干有出口，不再长期占 WIP。

一句话：**Notion 管早上开工，GitHub 管晚上裁决。**
