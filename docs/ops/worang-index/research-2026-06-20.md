# 沃壤 Index 研究 · 2026-06-20

## 0. 核心决策

- 本 Index 应成为 AI 冷启动的第一跳索引，但不替代 `README.md`、`AGENTS.md`、`CLAUDE.md` 与真实文件。
- `current.json` 保存机器完整事实账；`current.md` 只给人和 AI 看第一跳。
- 根部 Index 必须精要：只保留必要根、一句话职责与第一跳，不展开根目录清单，不复述白名单正文。
- GitHub workflow 可以自动维护可确定的生成物与仓内相对链接；语义归位、根目录白名单、入口定位、Notion 链接、外部 URL 仍交给谷判断。

## 1. 内部基线

### `README.md`

根 README 当前承担仓库总入口与空间判准：说明东西禾集、腐海 / 沃壤分工，以及 `成为/`、`领域/`、`资源/`、`wo/`、`docs/ops/`、`src/` 的一级入口。

### `AGENTS.md` / `CLAUDE.md`

二者承担代理冷启动与施工口径：命令、架构、数据源、约束、技能入口与关键文档。它们不是全仓目录，但会影响新代理从哪里进入。

### `docs/ops/root-manifest.json` / `scripts/root-guard.mjs`

`root-manifest.json` 是根目录机器账；root guard 负责守门。新的 worang Index 不替代它，也不修改根目录白名单。

### `wo/source-map.md`

`wo/source-map.md` 给出主源判准：Notion 是当前工作台；本地是可携带骨架；Git 是迁徙凭证。Index 的定位应服务可携带与可接续，而不是把 Notion 或 GitHub 复刻成目录树。

## 3. 断裂带

### AI 冷启动 vs 人类导航

AI 冷启动需要明确第一跳与禁区；人类导航可能希望看更多目录。当前优先级是 AI 冷启动，因此 `current.md` 必须薄。

### 全仓扫描 vs 不成厚目录

全仓扫描是机器事实账需求，不等于人读页面要展示全仓。解决方式：`current.json` 完整，`current.md` 精要。

### 自动维护 vs 人类语义判断

脚本能判断路径存在、hash、大小、层级模式、内部链接是否断。脚本不能判断某个材料是否应升级为入口、是否该外显、是否该修改根目录白名单。

### 根入口稳定 vs 入口新鲜度

根入口由白名单与 root guard 稳定；入口新鲜度由 Index 生成物与 workflow 维护。二者不互相替代。

### workflow 自动改写 vs 谷的合并裁决

workflow 只开维护 PR，不直推 main。机器负责发现与可确定修复，谷保留最终合并裁决。

### 机器完整账 vs 根部精要呈现

`current.json` 可完整承载全仓扫描事实；`current.md` 的根部只显示必要根和一句话职责，避免根部变成第二套白名单。

## 4. 价值排序结论

- 自动维护优先服务冷启动新鲜度。
- 不可越权改写语义入口。
- 机器只处理可确定事实。
- 维护 PR 保留谷的坍缩权。
- 根部 Index 只保留必要根、一句话职责与第一跳，不展开根目录目录树。

## 5. 结论

### Index 的最小职责

1. 给 AI 冷启动一个当前第一跳。
2. 用机器账记录全仓文件 / 层级 / 入口信号 / 链接状态。
3. 把异常显影出来，交给脚本或谷处理。
4. 明确哪些东西不能自动改。

### 文件落位

- `docs/ops/worang-index/research-2026-06-20.md`：本研究记录。
- `docs/ops/worang-index/index.schema.json`：索引契约。
- `docs/ops/worang-index/README.md`：维护说明。
- `docs/ops/worang-index/current.json`：机器生成索引。
- `docs/ops/worang-index/current.md`：AI 冷启动人读薄入口。
- `scripts/build-worang-index.mjs`：生成脚本。
- `scripts/check-worang-index.mjs`：验收脚本。
- `.github/workflows/worang-index.yml`：自动检查 / 维护 PR。

### 机器字段建议

字段以 `index.schema.json` 为准。核心包括 `path`、`kind`、`layer`、`entry_role`、`ai_use`、`source_status`、`maintenance`、`links`、`signals`、`display_scope`、`size_bytes`、`sha`、`warnings`。

### 验收方式

```bash
node scripts/build-worang-index.mjs
node scripts/check-worang-index.mjs
node scripts/root-guard.mjs
cargo test
```

### workflow 自动维护边界

可自动维护：`current.json`、`current.md`、可唯一确定目标的仓内相对链接。

只报警不自动改：语义入口、根目录白名单、Notion 链接、外部 URL、需要谷判断的归位。

### 根部精要显示规则

- `current.json` 可完整记录根目录和全仓事实。
- `current.md` 根部只显示必要入口。
- 不列工程配置、锁文件、脚本、workflow 等支撑项。
- 不复刻 `root-entry-allowlist` 与 `root-manifest` 的完整内容。
