# 沃壤 CLI 观察台

本页只回答一件事：**哪些外部 CLI 现在真的值得进入沃壤的注意力，以及证据走到了哪里。**

它不是软件推荐清单，不收录所有听说过、安装过或有人开过 Draft PR 的工具。发布外手仍由 `docs/ops/distribution-cli-registry.v0.md` 负责；本页只保存跨仓库使用的当前判断。

## 进入与退出

一个工具只在满足至少一项时进入本页：

- 已经在受控真实工作中持续使用；
- 已完成可回指的本地 probe / smoke；
- 当前确实需要一次采用、继续实验、拒绝或退役的判断；
- 已经 `REJECT` / `RETIRE`，且保留结论能防止重复踩坑。

只有文档、热度、安装成功、`--version` 成功或未合并 PR，不足以占一个条目。候选可以继续留在自己的 Issue / PR 中；没有进入本页不等于拒绝。

当一个实验不再需要人的判断、也没有已采用或已退役的事实值得长期保留时，它可以从本页退出。历史仍留在 Issue / PR，不再占据前台。

## 状态模型

| 状态 | 含义 |
|---|---|
| `WATCH` | 问题值得看，但尚无真实本地运行证据。 |
| `EXPERIMENT` | 已有有界 probe、smoke 或可审阅 wrapper，仍未形成稳定采用事实。 |
| `ADOPT` | 已在明确边界内进入 `main` 或受控真实工作。 |
| `REJECT` | 当前收益、风险或重复性不足；保留拒绝理由。 |
| `RETIRE` | 曾经采用，现已被替代、失效或长期不用。 |

状态是人的判断，不由 checker、安装结果、热度或 Agent 自动推进。

## 证据模型

| 证据 | 含义 |
|---|---|
| `DOCS_ONLY` | 只有说明、提案或间接资料。 |
| `LOCAL_PROBE` | 完成过一次有边界、可回指的本地调用。 |
| `REPEATABLE_SMOKE` | 成功与失败路径可以稳定复跑。 |
| `FORMAL_WRAPPER` | 已有窄 wrapper、doctor 或边界测试；是否进入 `main` 另写。 |
| `OPERATIONAL_USE` | 已在受控真实工作中使用并留下版本、边界或运行证据。 |

证据等级只说明“目前有什么”，不自动决定状态。Draft PR 中有 wrapper，仍然可以是 `EXPERIMENT`。

## 条目最小形状

```text
## CLI: NAME
- **状态 / 证据**：STATE / EVIDENCE
- **真实问题**：
- **已成立**：
- **边界**：
- **下一门**：
- **锚点**：
- **最后复核**：YYYY-MM-DD
```

未知事实直接写未知；不要为了填满字段而猜。checker 只检查格式、枚举、日期和明显的秘密 / 私人路径，不检查工具名单，也不替人判断是否应该采用。

## CLI: `nlm`

- **状态 / 证据**：ADOPT / OPERATIONAL_USE
- **真实问题**：在显式选择的 NotebookLM 来源中做带引用的跨材料检索，并为 `wo touch --nlm` 递送少量事实碎片。
- **已成立**：现役探针和 `wo touch --nlm` 路径已经进入 `main`，并有真实使用记录。
- **边界**：只读取显式选择的来源；不得把 NotebookLM 当事实母本或意义裁判；认证、上传与外部写入仍按各自动作守门。
- **下一门**：版本或认证边界变化时重跑真实 smoke；没有变化就不为“保持新鲜”机械更新。
- **锚点**：`scripts/nlm-grain-probe.sh`、`wo/nlm/`、Issue #81、PR #303。
- **最后复核**：2026-07-02

## CLI: `jq`

- **状态 / 证据**：ADOPT / OPERATIONAL_USE
- **真实问题**：为仓库脚本和本地 AI 提供稳定、可组合的 JSON 选择与变换。
- **已成立**：仓库现有脚本和本地验证持续使用 `jq`；它已是底层小工具，而不是待选产品。
- **边界**：只处理调用者显式传入的数据；不因为可组合就自动扩大到外部写入或私人正文汇总。
- **下一门**：只有现有脚本出现兼容性问题或版本迁移时复核。
- **锚点**：现有 `scripts/` 调用与 Draft PR #309 的边界整理。
- **最后复核**：2026-07-02

## CLI: `gitleaks`

- **状态 / 证据**：ADOPT / OPERATIONAL_USE
- **真实问题**：在提交或交付前发现凭据、token 与高风险秘密泄漏。
- **已成立**：多轮本地 staged scan 已真实运行；当前是人工 / 本地验证工具，不依赖 hosted CI 才成立。
- **边界**：扫描结果是证据，不自动改文件；未运行不能写成 PASS；是否进入 Git hook 仍由 PR #311 单独决定。
- **下一门**：若 #311 进入 `main`，复核 hook 的性能、误报与绕过边界；否则维持手动使用。
- **锚点**：本地 PR 验证记录与 Draft PR #311。
- **最后复核**：2026-07-02

## CLI: `duckdb`

- **状态 / 证据**：EXPERIMENT / FORMAL_WRAPPER
- **真实问题**：用可复跑 SQL 检查显式传入的 CSV、JSON、NDJSON 或 Parquet，而不是为每个问题重写临时脚本。
- **已成立**：实验 PR #327 已合并；Draft PR #333 已形成只读、内存态 wrapper 与成功 / 失败测试，但正式入口尚未进入 `main`。
- **边界**：只读、显式输入、不写 canonical；外部供应链、查询时限、输出上限与大输入临时空间仍是未闭合风险。
- **下一门**：只审 #333 是否把这些边界处理到可采用；未合并前不写成现役能力。
- **锚点**：Issue #312、PR #327、Issue #328、Draft PR #333。
- **最后复核**：2026-07-02

## CLI: `gws`

- **状态 / 证据**：EXPERIMENT / FORMAL_WRAPPER
- **真实问题**：给 Google Workspace 提供可审计、可超时、默认只读的窄调用入口。
- **已成立**：bridge 已通过 PR #305 进入 `main`；Draft PR #341 正在定义第一个只读 adapter 合同。
- **边界**：真实 Workspace smoke、实际版本和账户行为尚未验证；不把 bridge 存在写成真实账户能力，不自动扩大读取范围。
- **下一门**：先完成一次明确授权的真实只读 smoke，再决定 adapter 是否进入 `main`。
- **锚点**：Issue #315、PR #304、PR #305、Draft PR #341。
- **最后复核**：2026-07-02

## 当前不占前台的候选

`mise`、`yq`、`pandoc`、`watchexec`、`lefthook` 等仍可在各自 Issue / PR 中继续实验。它们没有被拒绝；这里只是不因 Draft 存在或资料齐全，提前把它们做成长期登记负担。
