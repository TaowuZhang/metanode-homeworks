# 豆瓣 mirror v0 开工说明

日期：2026-06-03
位置：资源库自动化候选 / 豆瓣书影音评分镜像

## 目标

把豆瓣账号里的电影、书籍、音乐评分 / 标记，沉成 GitHub 中可版本化、可检索、可重建的只读 mirror。

本轮不清理整个 `资源/`，也不重构旧目录。

## 为什么先做豆瓣

现有 `资源/电影/`、`资源/书籍/`、`资源/音乐/` 已经呈现出高度一致的豆瓣字段：标题、个人评分、打分日期、条目链接，以及电影上映日期、书籍作者 / 出版日期、音乐发行日期 / 音乐家等。

这说明豆瓣更像「账号评分镜像」而不是普通链接入口，适合进入机器同步区。

## 谷的补充口径

谷几乎把所有能在豆瓣记录的都记录在豆瓣；但音乐部分会更多使用 Apple Music，豆瓣音乐记录相对麻烦，不像电影和书籍那么顺手。

因此：

- 豆瓣 v0 仍以电影、书籍、音乐三类评分 / 条目标记为对象；
- 音乐不被解释成完整听歌史；
- Apple Music 是未来音乐行为源候选；
- 未来可研究 Apple Music 听歌行为 → 豆瓣音乐记录、阅读平台读书行为 → 豆瓣书籍记录的桥；
- 这些桥不进入 v0 mirror。

## 第一刀

第一刀先做容器和守卫，不碰外部账号：

- 新增 `资源/_douban/README.md`；
- 新增 `资源/_douban/manifest.schema.json`；
- 新增 `scripts/sync-douban.mjs`；
- 新增手动 dry-run workflow；
- 先支持 `existing-markdown` 种子模式，验证同步区、manifest、路径守卫。

真正接豆瓣账号同步时，再新增 `douban-account` 模式。账号信息只走 GitHub Secrets / 本地环境变量，不进聊天、不进仓库。

## 路径边界

同步器只允许写入：

```plain text
资源/_douban/
```

明确不允许写入：

```plain text
资源/电影/
资源/书籍/
资源/音乐/
资源/链接/
```

## 数据边界

豆瓣 mirror 保存：

- `type`：movie / book / music
- `douban_id`
- `douban_url`
- `title`
- `personal_rating`
- `rated_at`
- 类型字段：上映日期 / 作者 / 出版日期 / 音乐家 / 发行日期
- `original_path`：如果来自旧 Markdown 种子，则记录来路
- `synced_at`

不保存：

- cookie / token / 登录态；
- 私密账号信息；
- 和豆瓣无关的音乐收听行为；
- 微信读书 / 得到大脑 / Spotify / 网易云 / Apple Music 原始行为数据。

## v0 不做

- 不写回豆瓣；
- 不删除旧文件；
- 不覆盖人工内容；
- 不做全量资源库清理；
- 不把所有资源都自动化；
- 不定时自动跑。
