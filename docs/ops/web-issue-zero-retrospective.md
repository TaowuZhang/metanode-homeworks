# Web 第零期回顾｜从散点到现场

时间：2026-05-09
关系：补充 docs/ops/web-issue-zero-brief.md

## 这轮是怎么走到这里的

一开始的问题不是“网页怎么设计”，而是：个人网站能否不落入作品集、简历、Notion 公共页或漂亮模板。
我们先从三个物理意象进入：场刊、工作室、证据场。它们最初像是风格参考，后来被校正为三种组织方法：场刊负责入场，工作室负责重组，证据场负责显影来路。

随后我们把外部 UIUX 资料搬入当前 Notion：Shape of AI、AI-UX interactions、Refactoring UI、Laws of UX、Sajid Code UI。Apple Design 与 NNGroup 因体量过大暂未完整导入，于是先作为补审槽，不阻塞施工。

## 关键拼合

- Shape of AI 让我们看到界面不是页面，而是 Wayfinders、Inputs、Governors、Trust indicators 的组合。
- AI-UX 提供时代语境：多入口、过程可见、Human in the loop、上下文。但它也带来危险。
- Refactoring UI 把我们拉回施工纪律：先功能，后 layout；先层级，后装饰。
- Laws of UX 补上可用性刹车：认知负荷、心智模型、选择过载、渐进披露。
- Sajid Code UI 补落地手感：不要追求漂亮网站；可用性胜过原创；Typography 是首版重点。
- 终端桥让讨论变成沉积：方法文档、brief、commit、push 都成为证据。

## 关键决策

1. 不做“第一期”，先做“第零期试运行”。
2. 不把网站当完成品展示，而把生成过程本身作为材料。
3. 不用“意图驱动”作核心词，改成意志保护、反猜意图护栏、显式场位、观看姿势、靠近方式。
4. 不先做视觉稿，先做内容语法、物件语法、场位剧本。
5. 不等 Apple / NNGroup，先把可推进的部分沉地，等资料到齐后补审。

## 被否定的默认想象

- 场刊不是杂志模板。
- 工作室不是卡片墙。
- 证据场不是数据面板。
- AI 不是网站主语。
- 漂亮不是第一目标。
- 原创交互不天然更好。
- 资料总结不等于设计。
- 复杂性不能消失，只能转移。
- 用户行为不是让系统猜意图的许可。
- 第一使用者不是系统预测对象。

## 张力

最大的张力出现在“意图驱动”。AI-UX 的语言很容易把界面推向预测用户、猜用户、自动改写叙事。谷明确挑战：这不是我们要的未来，尤其不能变成“猜用户意图”的 UI 套壳。

后注｜2026-06-03 概念纠偏：这里的核心不只是从 intent-based experience 改为 explicit scene selection，而是从「意图保真」正名为「意志保护」。

- 「意图」容易被第三人称化：系统、工程师、模型都可以把它当成可预测对象。
- 「意志」是第一人称生成：它不是被识别的对象，而是在靠近、拒绝、选择和承担中练出来。
- 大厂工程语境常把「猜用户意图」当作能力；沃壤作为第一使用者空间，反而要保护不被猜、不被代替、不被自动补全。
- 所以目标不是 intent fidelity，而是 will protection / anti-intent-guessing / explicit scene selection。

第二个张力是“AI 相关”与“AI 产品”的距离。AI 是时代灯光，不是地基。三意象并不依赖 AI，它们更接近物理语法、来路、现场和克制。

第三个张力是“研究资料很多”与“必须继续施工”。Apple / NNGroup 很大，不能成为等待的借口。因此先把已有资料变成方法文档和第零期 brief。

## 收束

最终收束成一句话：

> 第零期不是展示网站，而是展示网站如何被生成：入口、物件、来路和护栏先出现，视觉和动效后到。

下一步不是继续抽象，而是把第零期的真实物件写成远看 / 中看 / 近看的内容语法，再转成 issue / object / scene 数据。
