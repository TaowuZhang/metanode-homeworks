## 1. 为什么需要这张索引

历史对话里的核心请求不是“再总结一下”，而是让克把已经发生的事实、未来应该继续的行动、项目本身该落的硬锚点，都更新到必要位置。

所以本索引不替代快照主文档，也不替代 Notion 驾驶舱；它只做 checkout 地图：

```text
过去行动 → 当前硬锚点 → 下一步动作 → 停止条件
```

## 3. 已经确定的原则

1. Notion 不是事实总账，它是前台、活现场、纸条和共同治理场。
2. GitHub Issue 是硬锚点，承接事实、停止条件、事故和下一步。
3. GitHub PR 是候选沉积与合流，不是所有任务的总面板。
4. GitHub Projects 以后只做视图层，不能抢事实本体。
5. 资源不是因为存在或能同步就更新，必须有内容角色。
6. 事故不是噪音，#171、#173、workflow 权限失败、#200 编号事故都要入镜。
7. 早上只给下一步，晚上才给判断。
8. 不要把接续入口做成漂亮全景墙。
