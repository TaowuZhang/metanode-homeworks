# 呈现层内容模型（2026-06-12 初稿）

来源：谷于 2026-06-12 Notion 对话中的两次设想（22:25 展物分层、22:39 内容四件），克补充骨架两样并沉淀成文。状态：初稿，供后续专题修订；`web/README.md` 在议栏指向本文作为展开。

## 一、内容四件（谷，内容类型轴）

一个页面 / 一个网站该呈现的信息，分四类：

1. **数据的分析整理** —— 图表、统计、可视化；类似做 PowerPoint 里的数据页。
2. **文字的观点呈现** —— 论点、叙述、判断。
3. **关键图片** —— 必须有，不是装饰而是信息。
4. **交互动画** —— 很棒的交互，让呈现活起来。

## 二、骨架两样（克补，托着四件，不与四件并列）

5. **选择结构（入口 / 导航）** —— 访客先于内容遇到的是「往哪走」。第零期 footer 原则「不猜访客意图，只响应选择」即此层雏形；同根灵感见 Shneiderman 入口原则。四件内容是展物，选择结构是展厅动线。
6. **证据来路（链接层）** —— 每件展物带回原文的路。第零期已给每个物件挂回 GitHub 的 evidence links；网页不是说明书而是本期入场册，入场册的价值一半在「由此进入」。

## 三、寿命三层（谷 22:25 设想，与内容类型轴正交）

- **一次展览件**：事件物，过期即收（如 `issue-zero.json`，「期」本身就是这个形态的实验）。
- **可复用 / 反复呈现件**：固定资产（如 `profile.json`、`objects.json` 中被临时借去布展的部分物件）。
- **灵活件**：随状态更新（如 `pulse.json`、`workbench.json`）。

两轴相乘：每件展物入场前先答两问 —— **它是哪类内容？它活多久？** 载体与数据结构随两个答案不同：一次展览件可以手工、可以脏；可复用件值得定字段、入架构；灵活件需要更新通道。

## 四、与外手议题的收敛（压轴记账）

- `ai-browse/` 维持休眠（#223）；真有登录态浏览需求时，按 MCP 新形态接入对话，不唤醒旧脚本（同 `workers/` 判例：旧件安睡，需求来了按新形态首部署）。
- **手的谱系与手的产出分开记账**：谱系（连接、技能、操缥动作谱）是可复用件；产出（单次采集、单次报告）是一次展览件。外手产出物进入呈现层时，按本文两轴归档。
