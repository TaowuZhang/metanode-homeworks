# TopHub 与 Folo 引导式复查约定（2026-07-04）

## 固定要回答的三个问题

本轮后续判断始终围绕以下三个问题，不因单个页面或大类切换而漂移：

1. TopHub（今日热榜）是否还需要新增新的来源；若需要，具体应补入七个分组中的哪一个，是否应以替换而不是扩容的方式处理。
2. TopHub 是否还需要新增关键词追踪器；同时区分关键词追踪与通知机器人，不能把两者混为一谈。
3. 在 TopHub 已购买永久会员、Folo 只使用免费计划且不准备付费的现实约束下，哪些内容应放在 TopHub，哪些应放在 Folo，怎样发挥两者各自真正有用的能力。

每个 TopHub 大类看完后，必须明确回答这三个问题，不能只留下零散的页面点评。

## 协作与判断位置

- 用户掌握页面选择、浏览顺序与是否继续点击的主动权。
- 用户会逐个提供目录、详情页、榜单页或追踪结果页。
- 助手不擅自重新浏览整个目录，不把“还能继续看页面”当成答案。
- 每收到一个页面，助手负责判断：
  - 页面实际是什么能力；
  - 它是否是可加入自定义分组的订阅节点；
  - 若可加入，应进入七个分组中的哪一组；
  - 若不可加入，它是否仍可作为按需查询、发现或核验工具；
  - 页面中哪些具体节目、作者、项目或来源值得进一步点开；
  - 进一步对象更适合 TopHub、TopHub 追踪、Folo 观察期、Folo 常驻、按需访问还是退出。
- 助手可以明确提出下一步最值得点击的具体对象，但不能替用户夺取浏览路线与最终选择。
- 微信中已有的大量公众号与订阅关系暂不迁移。先完成 TopHub 七分组与 Folo 的基本复查，再单独讨论微信来源是否需要转移、保留或仅作发现入口。

## 每个小标签的处理方式

对用户提供的每个完整小标签：

1. 核对页面标称节点数、实际出现节点数和分页是否完整；
2. 区分独立来源、同一内容池切片、聚合榜、搜索工具、陈旧接口和失真标签；
3. 与当前 72 个 TopHub 节点、27 个 Folo 来源和 6 个追踪器比较；
4. 给出每个节点的路由：
   - TopHub 常驻；
   - TopHub 替换候选；
   - TopHub 追踪；
   - Folo 候选；
   - 按需访问；
   - 排除；
5. 将闭环结论写入当前分支的对应审查文件；
6. 推荐下一张最有信息量的页面，但由用户决定是否提供。

不能因为目录节点很多而机械增加来源。必须说清楚新增后补了哪个当前缺口。

## 每个大类结束后的固定收口

当一个 TopHub 大类的全部相关小标签看完后，必须暂停进入下一大类，先完成以下动作。

### 第一步：回答三个问题

#### TopHub

给出精确动作清单：

- 新增什么；
- 替换什么；
- 删除什么；
- 为什么；
- 放入七分组中的哪一组；
- 是否改变总节点数和各分组数量。

不能只列候选。必须区分：

- 建议执行；
- 保留候选、暂不执行；
- 按需页面；
- 明确排除。

#### 追踪器与通知

分别回答：

- 是否增加关键词追踪器；
- 追踪词是否精确、有限、可闭环；
- 是否需要通知机器人或外部通知渠道；
- 为什么不应把普通信息流变成主动打断。

追踪器与通知机器人是两种不同能力，不能合并判断。

#### Folo

给出：

- 立即新增；
- 进入观察候选；
- 等复查后再决定；
- 已有重复来源；
- 不进入 Folo。

免费计划下不以填满额度为目标。必须优先避免 RSSHub 配额浪费、未读堆积和 TopHub/Folo 重复。

### 第二步：用户执行

助手给出少量、明确、可直接在 TopHub 或 Folo 页面执行的动作。

在用户提供“全部订阅节点”及相关分组页面，或明确报告完成前：

- 计划仍记录为待执行；
- 不把推荐写成真实订阅状态；
- 不提前改写最终节点总数。

### 第三步：页面证据确认后更新 GitHub

确认用户已实际执行后，至少同步以下文件：

1. `资源/雷达/TopHub 全部订阅顺序.md`
2. `资源/雷达/TopHub 使用配置.md`
3. `资源/雷达/订阅系统.md`
4. `docs/ops/subscription-system-closeout-20260704.md`
5. 当前大类的 closeout 文件

同时：

- 重新计算 TopHub 总数与七分组数量；
- 更新后续所有编号；
- 将“待执行”改成“已执行”；
- 保留新增、替换、删除的原因；
- 不修改没有发生变化的系统状态。

只有 Folo 真实发生改变时，才更新：

- `资源/雷达/订阅源账本.yml`

## Apple Podcasts 排行页面纠正

已查看：`https://tophub.today/apple/podcasts`

该页面的实际性质是 Apple Podcasts 榜单查询页，而不是普通 TopHub 订阅节点详情页：

- 可切换国家或地区；
- 可切换播客分类；
- 可选择音频播客或视频播客；
- 页面按排名列出节目；
- 每个条目的主要动作是打开 iTunes / Apple Podcasts；
- 当前页面没有显示“订阅此节点”或“加入自定义分组”的操作。

因此：

- 不再把“iTunes Store 中国区播客 Top100”误记为可以直接加入 `影游音乐` 的 TopHub 节点；
- 该页面属于按需使用的市场榜单与节目发现工具；
- 排名只说明 Apple Podcasts 当前榜单位置，不等于节目质量、用户适配度或持续收听价值；
- 页面中还混有英语学习、儿童故事、助眠、音乐合集和关键词型内容，不能把整页视为播客策展结果；
- 从该页发现具体节目后，应继续查看节目近期选题、更新状态、独立站与 RSS，再判断是否进入 Folo；
- 只对单期感兴趣时，直接在原平台收听，不必进入 Folo。

## 七分组复查时的最小判断框架

对每个候选来源或页面，依次回答：

1. **它是什么**：热榜、排行、连续更新源、作者/节目、官方公告、搜索工具、目录还是聚合页。
2. **它提供什么增量**：当前七组是否已经有同类能力，新增后究竟补哪个缺口。
3. **它的时间关系**：只看此刻公共回声，还是值得长期跟随更新。
4. **它的媒介关系**：标题列表已足够，还是图片、音频、视频、长文或项目发布本身必须被保留。
5. **它的正确位置**：
   - TopHub 分组：公共注意力、榜单、发现和横向比较；
   - TopHub 追踪：精确项目、产品、系统、版本或阶段性事件的跨来源回声；
   - Folo：少量具体来源的一手、连续和多媒体关系；
   - 按需页面：榜单查询、市场样本、搜索和临时核验；
   - 不采用：陈旧、失真、重复、营销或无法形成明确用途的入口。
