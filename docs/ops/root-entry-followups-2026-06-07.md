## UUID 链接处理规则

旧 Notion 导出链接分三类处理：

1. **能确认当前真实路径的**：改成干净 GitHub 相对路径。
   - 例：`成为/灵感 ...csv` → `成为/灵感.csv`。
2. **能确认对象已换承载形态的**：改到真实新承载物，并在必要处说明形态变化。
   - 例：旧 `脉搏 ...md` → `web/content/pulse.json` + 架构文档。
3. **不能确认或目标不存在的**：不保留假链接，不补造文件；改成明示未落地或指向相关但不等同的对象。

不做全仓一把梭替换。尤其是：

- CSV 内部的旧 Notion 占位或历史导出痕迹，先不批量改。
- 子层旧链接应按目录 / 项目分批处理。
- 每次只改能证明目标路径存在、且语义等价或已说明形态变化的链接。

## `资源.md` 与 `资源/README.md` 分工

结论：**两者互补，不合并。**

- `资源.md`：根目录快速入口，负责让人或代理快速进入活库与参考页。
- `资源/README.md`：资源层治理页，负责居留规则、资源更新宪法、候选闸、材料状态与维护原则。

本轮处理：

- 在 `资源.md` 加入指向 `资源/README.md` 的治理入口说明。
- 在 `资源/README.md` 加入反向说明：快速打开活库 / 参考页时先看 `../资源.md`。
