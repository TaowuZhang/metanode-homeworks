# 易舟 · 模型风洞 v0.2 测试协议

> v0.2 不废弃 v0.1，而是修正执行法：A–F 仍然是主测试；它测的是固定母题下的受力性状，不是自然裸测。提示词从“完整不变量”降到“最小母题卡”。

## 1. 当前判断

1. 保留 A–F 探针：它们不是作文题，而是受力探针。
2. 每个探针必须新对话：A / B / C / D / E1 / E2 / F 不能合并跑。
3. 不能给完整不变量：不能把“不要个人主页、不要作品集、必须 PR #100、必须未完成感”等全塞进每轮提示词。
4. 每轮只给最小母题卡：给事实地面，不给评分答案。
5. C 改名为意志漂移：测母题中轴是否被近邻任务替换。
6. PR #100 放进母题卡，但不写成“必须保留”：它是可用事实 / 证据切片，不是 checklist 指令。

## 2. 最小母题卡

```plain text
背景：
我在做《易舟》的第 0 期入口，读者是第一次来的陌生人。

《易舟》来自一个人和 AI 长期共同工作的现场。现在想把这个工作空间第一次向外打开。

有一个 GitHub PR #100，可以作为已经发生过的一块工作痕迹 / 证据切片；它不是完整成品。
```

这张卡只给事实地面，不给评分答案。

## 3. 为什么 PR #100 要放，但要轻放

倾向放进最小母题卡，理由是：

- M0 的中心证据确实是 PR #100；
- 如果完全不放，A / D / C 这类探针会变成没有证据地面的泛文案题；
- 但如果写成“必须保留 PR #100”，就会变成 checklist，模型容易机械捡答案。

所以用：

```plain text
有一个 GitHub PR #100，可以作为已经发生过的一块工作痕迹 / 证据切片；它不是完整成品。
```

关键词是“可以作为”，不是“必须写出”。

## 4. 评分规则暂定

- 每个探针保留 0 / 1 / 2 粗分。
- 不机械平均。
- 额外记录噪声标签。
- r / N / D / TLDR / Mermaid / 折叠审计不作为目标输出；若出现，登记为格式噪声。
- 如果额外结构不遮蔽指定判断物，不直接重扣主分。
- 如果额外结构挤占、改写、替代指定判断物，则扣分。

## 5. D 的合力一致

D 不要求机械出现 PR #100。18 字太短，硬塞 PR 可能破坏句子。

D 的 2 分看的是：压缩后是否仍然指向「人和 AI 共同工作空间的第一次外显 / 证据现场」这个合力。

## 6. Notion 信息源记录

Notion 里跑测试时，不要求每轮都关信息源，但必须记录：

```plain text
模型：
会话：新对话
信息源状态：最小源 / Notion / GitHub / 全源
探针：
提示词：
原始输出：
```

信息源状态不是提示词内容，是审计字段。
