# 借港 × 资源/ 审计 v0 · 2026-05-31

## 0. 审计对象

本次审计对象是 Notion 的 `借港 · 异域文明接驳处` 与 GitHub / 沃壤中的 `资源/` 目录。

- Notion 借港：外部 Notion 空间、仍在更新的外部参考入口、需要阅读现场和工作台形态的材料。
- GitHub `资源/`：已经导出、消化、版本化或可批量处理的资源地层。

本审计延续当前总原则：**Notion 留活现场；GitHub 留沉地层。**

## 1. 方法

按《审计》方法执行：

1. 覆盖图：先画清 Notion 借港与 GitHub `资源/` 各自实际覆盖什么。
2. 缺陷清单：只诊断，不在本报告中直接搬运、删除或重构材料。
3. 三要素检查：定义、职责、转场条件。
4. 体感信号：记录未来克容易走偏的位置。
5. 沉积：形成 GitHub 报告，供后续修理使用。

## 3. 缺陷清单

### D1. 借港当前定义是对的，但入口太薄

借港现在非常克制，只放 Will’s S Design Note 作为外部 Notion 主入口。这符合“活入口”定位，也避免了把 GitHub `资源/` 复刻回 Notion。

风险不在于错，而在于太薄：未来新增外部参考时，克可能不知道要不要并列放入借港，还是直接沉入 `资源/`。

建议后续小修：给借港补一张“进入 / 不进入 / 外运”的一屏判断表。

### D2. `资源/` 是沉地层，但内部状态混杂

`资源/` 里同时存在：

- 旧库导出，如 `印象.md` 这类索引；
- 大型清单/CSV，如书籍、得到、链接、电影、音乐；
- 转录/摘要，如 `BibiGPT/`；
- 课程或视频消化材料，如 `萃览/`；
- 操作参考层，如 `词元.md`。

这些都可以留在 GitHub，但它们的“熟化状态”不同：有的是原始导出，有的是半加工材料，有的是已经可用的操作参考层。当前目录名能看出主题，但不总能看出状态。

建议后续不急着重构目录，先补一个 `资源/README.md`，说明资源内部的几种状态：原始导出、半加工、可引用、操作参考。

### D3. 借港到 `资源/` 的转场条件已有，但还不够可执行

借港页已经写了若干后续判断点：停止更新、变厚、需要版本历史、需要进入 `资源/` / `领域/` / source pack、Notion 只剩展示入口、谷已经消化出摘录/判断/结构/作品材料。

这套判断是正确的，但未来执行时还缺少一个最短动作句：

> 外部空间还在生长、需要阅读现场：留借港；已经被谷消化成摘录 / 判断 / 结构 / 作品材料：沉 `资源/` 或 `领域/`；需要脚本/版本/批处理：沉 GitHub。

### D4. `资源/` 缺 README 是主要可修缺口

本轮读取发现 `资源/README.md` 不存在。

这会导致未来克进入 `资源/` 时只能从文件名猜：

- 哪些是旧库索引；
- 哪些是导出表；
- 哪些是可读材料；
- 哪些是课程/视频萃取；
- 哪些是操作参考；
- 哪些应该继续沉到 `领域/` 或 `成为/项目`。

建议下一步小修优先补 `资源/README.md`，不要先大搬目录。

### D5. Will’s S Design Note 不应搬运

Will’s S Design Note 是外部 Notion 设计参考空间，仍适合留在 Notion。它不是 `资源/` 的缺失目录，也不是应该被完整复制的 source pack。

正确做法是：保留入口；当谷学习后产生自己的摘录、判断、结构、作品材料，再按内容性质沉到 `资源/`、`领域/` 或项目地层。

## 4. 三要素检查

| 项 | 借港 | `资源/` |
| --- | --- | --- |
| 定义 | 外部 Notion 空间 / 活参考入口 / 阅读工作台 | 资源沉积层 / 导出与消化材料 / 可版本化地层 |
| 职责 | 提供进入外部材料的现场；保留是否外运的判断点 | 保存已导出、已处理、可检索、可批量处理、可引用的资源 |
| 转场条件 | 外部空间仍更新、仍需页面阅读、尚未消化时留借港 | 停止更新、变厚、需要版本化/脚本/批处理、或已被谷消化成材料时沉 GitHub |

## 5. 体感信号

1. 如果克想把 Will’s S Design Note 完整搬进 GitHub：多半是过度沉积。
2. 如果克想把 `资源/` 里的大清单搬回 Notion：多半是入口洁癖或可视化冲动。
3. 如果一个材料只是“别人还在维护的外部空间”：留借港。
4. 如果一个材料已经变成谷自己的摘录、判断、结构、作品、课程笔记或操作参考：沉 GitHub。
5. 如果资源材料需要批处理、版本、脚本读取或 source pack：沉 GitHub。

## 6. 当前结论

借港与 `资源/` 的大方向是自洽的。

借港没有变成资源目录，这一点很好；`资源/` 也确实承担了大量沉积材料，而不是活入口。当前主要缺陷不是边界错，而是 **GitHub `资源/` 缺入口说明，借港缺一个更短的转场判断表**。

所以后续不应大搬家，应做两处小修：

1. 给 `资源/` 补 README，说明目录角色和材料熟化状态。
2. 给借港补一张“留借港 / 沉资源 / 沉领域 / 沉项目”的转场表。

## 7. 后续处理建议

### 立刻可修

- 新增 `资源/README.md`：说明 `资源/` 是资源沉积层，不是活外部入口；列出典型子类和转场去向。
- 更新借港页：补一屏转场表，减少未来克猜测。

### 等触发再修

- `资源/` 内部目录重构暂不动。当前材料多、类型杂，贸然重构成本高，且没有明确收益。
- Will’s S Design Note 暂不外运，除非它停止更新或谷已经消化出自己的稳定材料。

### 暂不动

- 不把借港扩成外部资源总目录。
- 不把 GitHub `资源/` 搬回 Notion。
- 不把 `领域/` 与 `资源/` 合并。
