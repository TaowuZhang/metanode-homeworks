# 新建文件夹报告模板

当一次改动想新建长期文件夹时，先写这份报告；报告可以放在 PR 描述、issue、或同 PR 的 `docs/ops/` 审计记录里。

## 触发条件

满足任一条就必须打报告：

- 新建一级文件夹。
- 新建 `docs/` 下二级长期目录。
- 新建纯英文泛名目录，例如 `docs/classic/`、`docs/resources/`、`docs/notes/`。
- 新建临时目录但没有退场条件。
- 新目录会让 `成为/`、`领域/`、`资源/`、`技能/`、`wo/`、`docs/ops/` 的边界变模糊。

## 报告格式

```markdown
# 新建文件夹报告：<path>

## 1. 想解决什么问题

一句话说明新目录要承接的真实问题。

## 2. 为什么现有位置装不下

逐项回答：

- 为什么不是 `成为/`？
- 为什么不是 `领域/`？
- 为什么不是 `资源/`？
- 为什么不是 `技能/`？
- 为什么不是 `wo/`？
- 为什么不是 `docs/ops/`？
- 若是公开展示，为什么不是 `web/` 或现有 Notion 公开窗口？

## 3. 中文职责

用中文写一句目录职责。若只能用英文泛名说明，暂不准建。

## 4. 第一跳入口

- README：
- 根入口或上级入口是否同步：是 / 否，原因：
- `docs/ops/worang-index/current.md` 是否同步：是 / 否，原因：

## 5. 不放什么

列出至少三条明确不放的内容，避免目录膨胀。

## 6. 退场条件

满足什么条件后，这个目录应被合并、迁出、反哺或删除？

## 7. 本 PR 验收

- [ ] 已有 README。
- [ ] 已同步必要入口。
- [ ] 已说明退场条件。
- [ ] 未复制已有 GitHub 母本，未在 Notion 或其他应用重建第二套权威结构。
- [ ] 未把 `docs/` 扩成第二知识库。
```

## 快速判准

> 现有承重层解释不清，不准先塞 `docs/`；新目录不能只因“方便”而存在，必须说明它为什么比 `成为/`、`领域/`、`资源/`、`技能/`、`wo/`、`web/` 或 `docs/ops/` 更合适。
